# DeathBan Pro 1.3.0-alpha.1

A testing prerelease containing the October 9 persistence, shared-life, history, and PlaceholderAPI changes from PRs #64 and #66. The version advances beyond the earlier 1.2.0-alpha.1 feature release; it does not imply production readiness.

## Changes

- Hardened player, pending-ban, and shared-pool persistence with forced temporary-file writes and atomic replacement, immutable snapshots, and revision checks that prevent older asynchronous saves from overwriting newer state. Reload and shutdown flush outstanding state. Atomic replacement must be supported by the data filesystem; failed writes are reported rather than falling back to a potentially destructive replacement. This is not a guarantee against every power-loss scenario.
- Restricted shared-life refills and team membership changes, with matching command completion. Pool changes and player state remain available across restarts and mode changes.
- Added administrator-only `/deathban history <player> [page]`: the latest 100 ban, expiry, pardon, and reset events per player, ten per page, including original penalty details, team pool, and moderator identity where available. History survives restarts and offense resets. Expiry events are discovered lazily and retain the original expiry timestamp; events removed by older versions cannot be reconstructed.
- Added an optional built-in PlaceholderAPI expansion for remaining lives, offense level, ban time, team, and shared-pool capacity. PlaceholderAPI and scoreboard plugins are not bundled. No eCloud expansion download is needed. Callbacks use cached state on the server thread; asynchronous calls and missing player context remain unresolved. Uncached players use initial values.
- Fixed duplicate death protection so legitimate deaths after respawn count even within five seconds.
- Corrected the marketing website and expanded regression coverage for persistence, permissions, history, placeholders, and repeat deaths.

## Permission migration

`deathban.lives.add` and `deathban.team.manage` now default to operators. Players with only `deathban.use` can still read life status but cannot refill pools or create, join, or leave teams. Grant the new permissions only to explicitly trusted roles: refills and team switching can circumvent the intended shared-life challenge. `deathban.admin` alone does not grant these two permissions; `deathban.*` includes both. History requires `deathban.admin`.

Operators and roles with `deathban.bypass` bypass penalties by default. Use an ordinary player for enforcement tests and review existing wildcard grants before upgrading.

## Compatibility and verification

- Requires Java 21 or later and the Bukkit/Spigot API baseline declared as `api-version: '1.21'`; intended for Spigot/Paper 1.21+.
- Compiles against Spigot API 26.2. PR #66 reports Paper startup, reload, persistence, and shutdown checks on 1.21, 1.21.11, and 26.2. That is a recorded smoke-test matrix, not proof of every supported server/version/plugin combination; a separate Spigot runtime matrix and player-client playtesting have not been recorded here.
- Optional PlaceholderAPI must support your server version. The repository documents PlaceholderAPI 2.12.3 or later for 26.2; its compile-only baseline is 2.11.6.
- Main CI run [37976230840](https://github.com/KevinTCoughlin/deathban-pro/actions/runs/37976230840) passed on merged feature commit `831dfcbffc383e451f6d354d5121b52bc40813d9`. PR #66 reports 165 passing tests. Release publication runs Gradle `check shadowJar`, including packaging/runtime-helper tests, ktlint and detekt, and verifies the version embedded in `plugin.yml`.
- The shaded JAR includes Kotlin runtime helpers and relocated bStats. Spigot and PlaceholderAPI remain provided by the server.

## Upgrade

1. Back up the server and `plugins/DeathBanPro/`, and retain the previous JAR for rollback.
2. Stop the server, remove the old DeathBan Pro JAR, and install `DeathBanPro-1.3.0-alpha.1.jar` in `plugins/`.
3. Start a staging server first; confirm the logged plugin version, permission grants, and optional PlaceholderAPI registration.
4. Follow the [server-admin pilot checklist](https://github.com/KevinTCoughlin/deathban-pro/blob/main/docs/PILOT_CHECKLIST.md), including ordinary-player enforcement, pardon/reset during countdown, shared-life restrictions, restart persistence, and disposable crash-recovery tests. Validate scoreboards both with and without PlaceholderAPI installed.

Report exact server/Java/plugin versions and sanitized reproduction steps in [GitHub Issues](https://github.com/KevinTCoughlin/deathban-pro/issues).
