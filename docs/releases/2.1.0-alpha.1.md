# DeathBan Pro 2.1.0-alpha.1

A testing prerelease that moves player-facing text to the Adventure API and reports every invalid config value at once. Java 25 and Paper 26.3 are still required. Existing `messages.yml` files that use `&` or `§` color codes keep the same colors.

Java 21 and Minecraft 1.21 servers should stay on [v1.3.0-alpha.2](https://github.com/KevinTCoughlin/deathban-pro/releases/tag/v1.3.0-alpha.2).

## Changes

- Kicks use `kick(Component, PlayerKickEvent.Cause.PLUGIN)`. Death-ban titles use `showTitle` with the same 10 tick fade-in, 70 tick stay, and 20 tick fade-out.
- Active bans are denied on `PlayerConnectionValidateLoginEvent` with a component message, after the async player-data preload. Paper runs that event during login and again at the end of configuration; expiry handling stays idempotent.
- `messages.yml` and built-in theme strings are parsed as MiniMessage (`<red>`, `<bold>`, `<#ff5555>`). A value that contains legacy `&` or `§` codes is read with Adventure's legacy serializer instead. Placeholders such as `{player}` are inserted as plain text.
- `config.yml` validation collects every invalid mode, threshold, pool size, duration, and ban-duration entry into one error. `/deathban reload` still keeps the previous configuration when validation fails.

## Player-visible text

- Default messages and legacy color configs render the same words and colors.
- A value with no legacy codes is now MiniMessage. A previous config that showed a literal tag such as `<red>` will now apply that formatting.
- Built-in themes still return source strings. Those strings use `&` codes and are parsed when displayed.

## Upgrade

1. Back up the server and `plugins/DeathBanPro/`.
2. Stay on Java 25 and Paper 26.3.
3. Replace the JAR with `DeathBanPro-2.1.0-alpha.1.jar`.
4. Start a staging server. Invalid config now lists every problem instead of stopping at the first one.
