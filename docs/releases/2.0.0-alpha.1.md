# DeathBan Pro 2.0.0-alpha.1

A testing prerelease that moves DeathBan Pro to **Java 25** and **Paper 26.3**. The major version changes because Java 21 and Minecraft 1.21 servers are no longer supported. Penalty behavior is unchanged: one death costs one life or one ban.

Java 21 and Minecraft 1.21 servers should stay on [v1.3.0-alpha.2](https://github.com/KevinTCoughlin/deathban-pro/releases/tag/v1.3.0-alpha.2).

## Changes

- Compiles and tests against Paper API `26.3.build.237-stable` instead of the Spigot API. `plugin.yml` declares `api-version: 26.3`.
- Java 25 toolchain, Kotlin JVM target 25, and Temurin JDK 25 in CI and release builds.
- The JAR is multi-release. On Java 21 it logs `DeathBan Pro requires Java 25 and Paper 26.3` and disables itself instead of failing with `UnsupportedClassVersionError`.
- New tests: fire deaths in shared mode (one life lost) and individual mode (one ban, cause `FIRE`), `deathban.bypass` immunity to fire, plugin-set and default respawn locations left unchanged, and the multi-release JAR choosing the right entry point.

## Paper 26.3 behavior this release was checked against

- Build 228: standing in fire now fires `EntityDamageByBlockEvent`. DeathBan only counts `PlayerDeathEvent`, so a fire death is still counted once.
- Build 229: cancelling `PotionSplashEvent` keeps fires lit. DeathBan does not cancel splashes; another plugin that does can leave a player in fire, and that death counts once.
- Build 233: respawns with no bed or anchor can land anywhere in the `respawn-radius` square. DeathBan does not move the player.
- Minecraft 26.4 is not supported yet. DeathBan sends no login packets, but proxies and packet libraries need 26.4's new login acknowledgement before 26.4 clients can join.

## Compatibility and verification

- Requires Java 25 and Paper 26.3 (build 237 or later recommended).
- Main CI passed on merge commit `1555dfa` of [#74](https://github.com/KevinTCoughlin/deathban-pro/pull/74), with 171 tests.
- The release JAR loaded and enabled on Paper 26.3-238 with Temurin 25.0.5 alongside Geyser 2.12.1, Floodgate 2.2.5, Multiverse-Core 5.8.2, Parkour 7.2.8 and WorldEdit 7.4.6. `/deathban` responded from the console.
- Not yet recorded: player-client tests of the fire, potion and respawn cases, and a live Java 21 start of the guard. The guard is covered by the JAR test only. See the manual checklist in #74.

## Upgrade

1. Back up the server and `plugins/DeathBanPro/`, and keep the previous JAR for rollback.
2. Move the server to Java 25 and Paper 26.3.
3. Replace the old JAR with `DeathBanPro-2.0.0-alpha.1.jar`. Config and data files are unchanged.
4. Start a staging server first and confirm the logged version. Then follow the [pilot checklist](https://github.com/KevinTCoughlin/deathban-pro/blob/main/docs/PILOT_CHECKLIST.md) with an ordinary player account.
